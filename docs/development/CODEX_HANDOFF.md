**Потік/Excel → AI-скринінг → сортування / score → картка тендера → AI-рекомендація → "Взяти в роботу" → менеджер / pipeline.**

«Фільтруючі елементи до тепловозів». Через це автокран XCMG / DONGFENG показують LF9009 та фільтри.

### Зробити 2 типи detail-flow

1. `topCategory === "Запчастини"`
   - залишити каталожні номери, бренди, кількість, аналоги;
   - showcase: `UA-2026-08-25-006722-a`.

2. `topCategory === "Техніка"`
   - НЕ показувати LF9009/FS19532 та інші filter-specific дані;
   - специфікація має бути технічною;
   - документи, AI-summary, ризики і план дій теж мають залежати від техніки.

## Інші відомі проблеми

- `src/routes/profile.tsx` імпортує `ProfilePage`, але в поточному `pages.tsx` його немає — додати мінімальну сторінку профілю.
- Перевірити TypeScript/build errors у `pages.tsx` і profile route.
- Settings → AI ще не повністю консолідований; це другий пріоритет після стабілізації demo-flow.
- Старі `/rules`, `/knowledge`, `/pipeline`, `/inbox` можна залишити як compatibility routes, але не повертати їх у sidebar.
- У `common.tsx` preview-текст ще каже «перевірити наявність» — прибрати.
- `Pipeline()` досі має колонку `Постачальники`; для alpha її прибрати або замінити на `Уточнення`.
- `Settings → Integrations` досі показує 1С та постачальника — залишити лише компактний Coming soon / Pro або прибрати з presentation flow.

## Примітка про пакет

З Lovable витягнуто весь прикладний TenderPro-код, маршрути, конфігурацію, стилі та runtime-потрібні UI primitives.
Не включено `node_modules`, lockfile, binary favicon та невикористаний shadcn/UI boilerplate — вони не потрібні для редагування логіки й можуть бути відновлені залежностями/генератором.
`src/routeTree.gen.ts` — generated artifact; TanStack Router має перегенерувати його з file routes.
